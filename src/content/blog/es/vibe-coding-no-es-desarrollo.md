El vibe coding es fácil de entender: describes una aplicación, la IA escribe el código, pruebas el resultado y pides correcciones. Una persona sin experiencia técnica puede tener una primera versión en pocas horas.

Eso es útil. Permite comprobar una idea antes de contratar un equipo o dedicar varias semanas a desarrollarla. El problema aparece cuando esa primera versión se publica como si ya fuera un producto terminado.

## Una demostración no cubre todos los casos

Google explica que el vibe coding funciona bien para aplicaciones sencillas y prototipos. Cuando el producto recibe muchos usuarios, todavía hacen falta conocimientos de programación y más precisión.

Una pantalla que carga correctamente no te dice qué ocurrirá si falla el pago, si dos personas editan el mismo registro o si alguien intenta acceder a datos ajenos. Tampoco explica cuánto costará operar el servicio ni cómo se actualizará dentro de seis meses.

La IA puede escribir código para esos casos, pero necesita instrucciones claras y una revisión cuidadosa.

## Revisar importa más que escribir el prompt

Pedir una función es la parte rápida. Después hay que leer los cambios, ejecutar pruebas y revisar los permisos. Si el agente quiere modificar veinte archivos para resolver un problema pequeño, conviene entender por qué antes de aceptar.

También hay que saber detenerse. A veces resulta más barato rehacer una parte que seguir corrigiendo una solución que nació con una estructura equivocada.

## Para qué sí lo usaría

Usaría vibe coding para crear una prueba de concepto, automatizar una tarea personal, preparar una herramienta interna pequeña o enseñar una idea a posibles usuarios.

También puede ayudar a un desarrollador con experiencia. El agente se encarga de trabajo repetitivo mientras la persona revisa arquitectura, seguridad y comportamiento.

## Antes de publicarlo

Haría una pregunta muy sencilla: ¿quién podrá mantener esta aplicación cuando el chat donde se creó ya no esté disponible?

Si nadie entiende el código, todavía es un prototipo. Puede ser un buen prototipo y cumplir perfectamente su objetivo, pero no conviene tratarlo como un sistema listo para clientes.

El vibe coding reduce el tiempo necesario para probar una idea. Las pruebas, la seguridad y el mantenimiento siguen siendo parte del desarrollo de software.
